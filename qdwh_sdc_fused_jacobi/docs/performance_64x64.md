# 64x64 融合 QDWH + SDC + Jacobi 性能研究

服务器代码位于 `/home/zhushengrui/project/svd/qdwh_sdc_fused_jacobi`。当前 host 在一次 ACL launch 中完成 QDWH、SDC 和叶块 Jacobi，64x64/batch=1 的融合 kernel 中位数为 4.102 ms，p95 为 4.124 ms。独立 QDWH+SDC 与独立 Jacobi 的中位数之和为 6.278 ms；融合节省 2.176 ms（34.7%）。完整数值校验通过：sigma 对 NumPy SVD 的最大绝对误差 1.481e-6。

## 本轮测量结论

64x64 热路径当前由 Jacobi 的成对列旋转主导。这个尺寸只有一个 SDC 叶块，`JacobiAiv()` 将整个叶块交给一个 AIV，其余 AIV 没有可领取的叶块。将 64 行 DMA 换成一个 16 KiB 连续 DMA 后，五次计时中位数从 4.166 ms 变为 4.160 ms，差异小于噪声，因而没有保留该代码路径。尝试跳过对称化也没有通过完整 SDC 校验，正式实现继续对叶块对称化。

把最大 sweep 从 30 降至 10，在 cond=100 和 cond=1e4 的样例上可把 64x64 延迟降到约 2.2 ms，并通过当前绝对误差容差。但 cond=1e6 样例上，小奇异值的相对误差明显变差：10 sweeps 的最大绝对误差为 1.187e-5，而 30 sweeps 为 5.307e-7。因此正式默认仍是 30 sweeps。

## 建议的实现方向

1. **跨 AIV 并行一轮里的独立列对。** 64 列可在每轮安排 32 对互不重叠的列，每个 AIV 负责一对的 64 行点积和旋转；一轮结束后同步，再进入下一对列排列。这直接利用当前闲置的 AIV，最可能降低小 batch 延迟。实现时应先测每轮的全 AIV 同步、列读写 GM 和 UB 占用；用 cond=100、1e4、1e6 检查 sigma。
2. **保留自适应精度保护。** 30 sweep 保持默认。若之后需要针对已知低条件数工作负载降低上限，提供显式可调 sweep 参数，并在文档中说明误差边界；不要只用矩阵边长自动选择 10 sweep。
3. **测分阶段开销后再改数据搬运。** 64x64 的单次 DMA 没有改善总延迟，说明进一步减少输入搬运指令收益有限；下一轮 profiling 应把时间拆到每轮旋转与同步，优先优化旋转调度。
